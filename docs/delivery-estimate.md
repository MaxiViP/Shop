# Предварительная стоимость доставки

Калькулятор доступен без входа на `/delivery` и в окне из полосы под шапкой.
Для авторизованного покупателя автоматически выбирается сохранённый адрес
(последний выбранный ID в этом браузере, иначе основной, иначе первый).
Цена показывается до наполнения корзины. Выбранный адрес переносится в оформление;
оценка повторяется в корзине. Бесплатная доставка определяется серверным расчётом
корзины и имеет приоритет над ориентиром перевозчика.

`POST /api/delivery/estimate` принимает только город, улицу, дом, необязательный
корпус/строение и пару координат `lat`/`lng`. Для расчёта используется
`offers/calculate` Яндекс Экспресс с примерным грузом 5000 г, 40 × 30 × 30 см.
Стоимость берётся с НДС, переводится в целые копейки на сервере. Контакты
покупателя не передаются, заявка не создаётся, заказы и финансовые поля не меняются.
Размер и вес условного груза указаны покупателю; окончательная цена уточняется
после сборки перед оплатой доставки по существующему процессу.

## Настройка

API использует существующие серверные `YANDEX_DELIVERY_*`: token, адрес,
имя, телефон и email точки отправления; координаты отправления необязательны.
`YANDEX_DELIVERY_ENABLED=false` отключает интеграцию, включая оценку.
При отключённом API или ошибке показывается сообщение с повтором, выдуманной
цены нет. Токен нельзя помещать в публичные переменные Nuxt.

Карта подключается отдельно через публичные переменные окружения web:

```dotenv
NUXT_PUBLIC_YANDEX_MAPS_KEY=
NUXT_PUBLIC_YANDEX_SUGGEST_KEY=
```

Для карты нужен ключ JavaScript API Яндекс Карт 2.1 с разрешённым геокодированием.
Для подсказок в поиске карты используется отдельный ключ Геосаджеста, если он подключён.
Ограничьте ключи доменом магазина в кабинете Яндекса. Подключение платных тарифов
не выполняется приложением; лимиты и право использования определяются условиями Яндекса.
Без ключа карты остаётся ручной ввод адреса и расчёт через API доставки.
JS API загружается только по нажатию «Выбрать на карте», не при автопоказе оценки.

## Обновление и ограничения

Сервер хранит до 256 оценок в памяти до 2 минут, но не дольше срока оффера.
Совпадающие одновременные запросы объединяются, не более 16 разных расчётов
одновременно. Публичный endpoint ограничен 20 запросами/IP и 300 запросами
всего за минуту на процесс. Для нескольких экземпляров API нужен общий лимит
на доверенном ingress. `TRUST_PROXY` настраивается по существующим правилам.
HTTP-ответы не кэшируются публичными прокси.

Клиент использует свежий результат при переходах, проверяет актуальность раз в
30 секунд в видимой вкладке и при возвращении. После ошибки автоматический повтор
не раньше минуты. Старая оценка помечается, адресные гонки игнорируются.
При выходе из аккаунта адрес и оценка очищаются. В localStorage хранится только ID
выбранного сохранённого адреса, с привязкой к аккаунту; доступность адреса повторно
проверяется по `/addresses`. Ручной адрес живёт в памяти до перезагрузки.

Проверки без реальных заказов курьеру:

```powershell
pnpm --filter api exec vitest run src/delivery/estimate.spec.ts src/delivery/yandex.service.spec.ts
node --test apps/web/test/delivery-estimate.test.mjs
pnpm typecheck
pnpm lint
pnpm build
node apps/web/test/delivery-estimate.smoke.mjs
```
