# Telegram UX 3.4 — покупка из категории

Проверки восстановления видимых кнопок после `cf21c44` (2026-10-24): Telegram/CartService 862 passed, Linux screen regressions 64 passed, полный Telegram PostgreSQL E2E 185 passed / 0 failed / 0 skipped одним прогоном в изолированной БД. API typecheck (оба конфига), lint, build и diff-check прошли. Реальный preview: send/edit HTTP 200, 4 Collage по 2 фото и 8 отдельных `buttons`-рядов товаров; байты JPEG сверены с product ID, повторное открытие без загрузок. Preview реальной корзины: 4 отдельных ряда по 4 кнопки с `align: right`. Корзина, заказы и адреса не изменились. Журналы: `work/telegram-ux34-visible/`. Успех API не доказывает видимость в Desktop/Android; перед выпуском нужно новое пользовательское подтверждение этих preview.

Причина регрессии `cf21c44`: Telegram сохранял `Photo.caption.text` с RichTextButton, но пользователь сообщил, что Desktop/Android не показывают эти кнопки. При этом renderer удалял соответствующие обычные строки как дубли. Теперь после каждого строго парного [Collage](https://core.telegram.org/bots/api#inputrichblockcollage) идут реальные `buttons`-блоки: `[Слева · название/цена][Добавить в 🛒]`, затем `[Справа · название/цена][Добавить в 🛒]`. При наличии товара его `−`/`+` находятся сразу после его основного ряда. Позиционные подписи явно связывают товар с левой/правой фотографией, без обещания равной ширины колонок. Дедупликация учитывает только настоящий отдельный `buttons`-блок; скрытая подпись фото больше не может убрать интерактивные строки.

Подтверждённое количество остаётся в кнопке названия/цены. Нечётная последняя позиция дополняется нейтральным слотом 4:3 без действий; отсутствующее фото заменяется таким же слотом без сдвига кнопок. Заглушка JPEG создаётся один раз в памяти, не меняет оригиналы или image runner и не запрашивается по внешнему URL. Длинные совпадающие названия различаются стабильным product ID. Фото остаются без нарисованных подписей. Сохраняются 8 товаров на странице, JPEG 4:3 и отдельный bot-specific кеш file_id миниатюр/полноразмерных карточек. При отказе медиа отдельные `buttons`-блоки остаются; HTML fallback использует те же строки клавиатуры. Нет fallback с одной фотографией в ряду.

Корзина сохраняет один реальный ряд `[Название][−][+][✕]` на позицию. Лимит названия увеличен с 16 до 40 символов, весь ряд имеет нативный `align: right`, а CUSTOMER renderer сохраняет явно заданное выравнивание. Управление оказывается у правого края; название первое слева внутри ряда. API не поддерживает отдельное выравнивание кнопки или растягиваемый промежуток, поэтому при коротком названии его нельзя одновременно прижать к левому краю всего сообщения. Нет CSS, невидимых пробелов или inline-кнопок вместо настоящего блока. Количество, стоимость, общий итог снизу и финансовые расчёты сохранены. В HTML остаётся стандартная четырёхкнопочная inline-клавиатура без неподдерживаемого `align`.

Прямое добавление использует существующие CartService и adjust: компактный внутренний callback `s:j` имеет ту же структуру и длину, что `s:u`, и добавляет только признак возврата в категорию. Парсер требует конкретную категорию и страницу. Существующие callback товара/корзины/быстрых покупок совместимы. Первый шаг — актуальный min, последующие — step; недопустимое уменьшение и предел переменного веса не предлагаются. Сервер повторно проверяет единицу и правила продажи. При устаревшей revision выполняется только чтение, при потерянном результате нет автоматического повторения мутации. Подтверждение и новые кнопки строятся по возвращённому CartService snapshot. Пагинация сохраняется; уведомление заменяется и исчезает при обычном открытии страницы.

Карточка товара показывает явное первое действие с количеством и предварительной/неизвестной стоимостью. После добавления основные кнопки называются «Уменьшить»/«Увеличить» и находятся в одной строке. Полное количество и серверная стоимость выделены в Rich и HTML. Ценовая дельта не добавляется к подписи кнопок изменения количества. Предварительные значения и неизвестная стоимость не превращаются в фактическую цену или ноль.

Без подтверждённого собственного Telegram-телефона категория читает только публичные товары: вместо мутации — существующее подтверждение телефона. Сохранённый callback также проходит авторизацию заново. HTML fallback содержит те же product ID, ревизии и строки кнопок без повторного текстового списка. Ошибки Telegram обрабатываются существующим транспортом отдельно от бизнес-операции.

[InputRichBlockButtons](https://core.telegram.org/bots/api#inputrichblockbuttons) имеет `align` только у всего ряда и допускает 1–8 кнопок. [RichMessageButton](https://core.telegram.org/bots/api#richmessagebutton) не имеет ширины, растяжения или выравнивания отдельного элемента. API не возвращает клиентские координаты; фактическая видимость и расположение проверяются отдельно в Desktop/Android. Предыдущее подтверждение caption-варианта не применяется к новому исправлению.

CartService, расчёты/скидки, checkout, оплата, взвешивание, STAFF, Rich policy, глобальные меню команд, Mini App, Prisma, image runner и Web не изменяются. Выпуск только API с проверенным backup/откатом и сохранением текущего глобального Rich.

Проверить в Desktop/Android: категорию из нескольких страниц, первое добавление, количество/`−`/`+` на той же странице, возврат из карточки, min больше step, весовые/штучные/упаковки/пучки/целые экземпляры с переменным весом, повторный/старый callback, длинные названия, первую большую кнопку карточки и формат неизвестной стоимости. Неподтверждённый аккаунт должен получить запрос телефона вместо изменения корзины.
