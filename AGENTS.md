# Shop

Продакшен-ориентированное приложение доставки продуктов с московского рынка.

## Стек

- Монорепозиторий на pnpm
- Frontend: Nuxt 4, Vue 3, TypeScript, Nuxt UI, Tailwind CSS, Pinia
- Backend: NestJS, TypeScript, REST
- База данных: PostgreSQL
- ORM: Prisma 7
- Валидация: Zod

## Стиль кода

- Код должен быть минимальным, читаемым и строго типизированным.
- Не использовать `any`.
- Не создавать лишние абстракции.
- Избегать дублирования логики.
- Использовать короткие и понятные имена файлов и папок.
- Для собственного CSS использовать BEM.
- Не создавать generic repository, base CRUD service и подобные абстракции без реальной необходимости.
- Backend является источником истины для цен, итоговых сумм, скидок и стоимости доставки.
- Деньги хранить целыми числами в копейках.
- Вес хранить целыми числами в граммах.

## Vue

Во всех Vue/Nuxt SFC соблюдать строгий порядок секций:

1. `<template>`
2. `<script setup lang="ts">`
3. `<style scoped>`

Использовать Nuxt UI и Tailwind там, где это уместно.

Для собственного CSS использовать BEM.

## Backend

Соблюдать структуру:

Controller -> Service -> Prisma

В относительных TypeScript-импортах использовать расширение `.js`, так как проект работает через ESM/NodeNext.

Не размещать административные мутации в клиентских endpoint'ах.

## Авторизация

- Авторизация покупателя: телефон + одноразовый код.
- Постоянных паролей нет.
- Сессия хранится в HttpOnly cookie.
- Гостевой checkout должен работать без авторизации.
- Гостевые заказы используют отдельную HttpOnly cookie гостевой сессии.
- После подтверждения телефона пользователь может получить гостевые заказы только если телефон заказа совпадает с подтверждённым телефоном пользователя.

## Роли

- USER — покупатель.
- SELLER — продавец / сборщик заказов.
- ADMIN — полный администратор.

SELLER и ADMIN могут работать с исполнением заказов.

Только ADMIN может управлять административными функциями магазина, например:

- товарами;
- категориями;
- сотрудниками;
- настройками.

## Заказы

Статусы заказа:

- NEW
- CONFIRMED
- ASSEMBLING
- READY
- DELIVERING
- COMPLETED
- CANCELED

Статусы позиции заказа:

- PENDING
- PICKED
- MISSING

`qty` — количество, заказанное покупателем.

`actualQty` — фактическое количество, собранное продавцом.

Для весовых товаров:

- количество покупателя должно соответствовать настроенному шагу продажи;
- фактическое количество при сборке может быть любым положительным целым числом граммов.

Frontend не должен вычислять или отправлять доверенные цены.

Backend самостоятельно рассчитываетcodex:

- `actualTotal`;
- `finalSubtotal`;
- `finalTotal`.

## Безопасность миграций

Перед изменением Prisma schema:

- проверить существующие миграции;
- сохранять существующие данные;
- не использовать `prisma migrate reset`, если пользователь явно этого не попросил.

После значительных изменений запускать:

- `pnpm exec prisma format`, если менялась Prisma schema;
- `pnpm exec prisma validate`, если менялась Prisma schema;
- `pnpm exec prisma generate`, если менялась Prisma schema;
- проверку TypeScript;
- lint;
- build, если это практически возможно.

Не добавлять в git секреты, `.env` и чувствительные данные.
